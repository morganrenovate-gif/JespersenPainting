# Historical job-cost schema v1 (DATA-003) and calculation v1 (DATA-006)

`job_cost.schema` is a Python standard-library, immutable, deterministic **in-memory contract**, not a database migration, workbook adapter, importer, or calculation engine. `JobCostDocument.schema_version` identifies this shape. Later adapters must declare their own version and emit one document per source workbook; unknown shape has no adapter selection. Importers should key replay/checkpoints by governed-storage source ID + original-byte SHA-256 + parser/adapter/schema versions, and keep item-level import errors and progress outside this document. This schema does not assert batch import, workbook detection, or deployed acceptance.

- `SourceWorkbook` carries governed source identity, immutable hash, shape state/version and parser/adapter versions. No source bytes or paths are stored here.
- `SourceRecord` groups one job and zero or more labor, material and revenue rows. Revenue rows can represent invoice, payment or other revenue evidence via `entry_type`; amounts and source subtotals are evidence, not assumed cash or recognized revenue. Row IDs and fact IDs are unique **within a document**, and should be stable across replay of the same adapter version. A labor label is not an employee identity mapping. Material/vendor and invoice references are labels, not deduplicated identities.
- Every defined field is present with an explicit `present`, `missing`, `unknown`, `malformed`, or `unsupported` state. A present field retains literal extracted text, a sheet/cell locator and a strictly typed normalized value; optional formula text is preserved as unevaluated evidence. A non-present field has no normalized value, but may retain raw text and provenance when available (e.g. malformed cell). Absence never means zero. Decimals are finite `Decimal` objects only (no float conversion). Text is not coerced into a financial value.
- `DerivedMetric` is separate from source facts. A computed metric requires input fact IDs and a calculation version; unknown/unsupported metrics carry a reason instead of an invented number. No computed metric automatically becomes accounting truth.
- `Discrepancy` links a numeric source fact to a metric; `differing` retains the signed **computed minus source** delta, while `unresolved` records comparisons not supported by current evidence. Discrepancies do not alter source or computed values. Downstream reconciliation should record coverage/comparison policy and not assume a missing discrepancy means agreement.

## Repository-only recomputation (DATA-006)

`job_cost.calculation.recompute(document, evidence)` returns a new schema-valid `JobCostDocument`, replacing prior derived metrics/comparisons deterministically while leaving its workbook, job and rows untouched. `CALCULATION_VERSION = job-cost-calculation/1`. An adapter/caller must supply `CategoryEvidence(category, state)` for each of `labor`, `material`, `revenue`, `payments`: `complete` asserts **all rows** in that category were enumerated, `incomplete` says coverage cannot be guaranteed, and `unsupported` says the shape cannot supply the category. Missing evidence defaults to incomplete. Even with complete coverage, an empty row set is unknown (not an implicit zero); an explicitly present zero amount/component can produce zero. Any missing/malformed/unknown component blocks that total; unsupported evidence yields unsupported. A row with unknown/unrecognized `entry_type` blocks both revenue and payments; only exact `invoice` or `revenue` entry types contribute to revenue, and only `payment` contributes to payments. No currency conversion, deduplication, or source-total fallback is attempted.

Labor uses only `hours × hourly_cost` per row; materials use only `quantity × unit_cost`. Revenue and payments sum only their respective `amount` facts. Total cost = labor + materials; gross profit = revenue - total cost; gross margin = gross profit / revenue (a ratio, not percent). Dependencies must be computed; zero revenue leaves gross margin unknown without division. Operations are Decimal-only without explicit rounding or quantization; division follows Python's active Decimal context. Callers requiring a prescribed currency scale or rounding policy must define one separately, not infer it from workbook totals. The calculation version identifies this policy and its fixed enumeration order. Input fact IDs track examined components and revenue classification (including blockers); for combined metrics they are the union of prerequisite fact IDs. Coverage assertions are supplied separately, not disguised as source facts. Job-level source totals are **comparison-only**: unequal supported totals get signed discrepancies, unavailable comparisons get `unresolved`, and equal values have no discrepancy in schema v1. A missing discrepancy is therefore not proof of agreement. No source facts or accounting truth are overwritten.

This repository-only synthetic implementation does **not** demonstrate real-workbook corpus coverage, representative manual reconciliation, integrated staging acceptance, or any production capability. Real workbooks require governed storage, adapter coverage evidence and independent QA before such claims.

Source raw text, formulas, names, amounts, and file hashes from **real** workbooks must remain in governed private storage, never public fixtures/logs. The tests use invented synthetic values only. Run the tests with `python -m unittest discover -s tests` in a Python environment; the trusted repository workflow is responsible for executable verification and the public-data gate after implementation.
