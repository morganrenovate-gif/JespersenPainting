# Hedy financial store source adapter

Synthetic source only. `createHedyStore` uses Hedy's documented `getWithMeta`, conditional `put(ifVersion)`, and immutable `put(ifNotExists)` primitives. Supply a runtime-owned SHA-256 function and trusted clock. No provider, credentials, private profiles, deployment, or schedule is included.

Each item is stored in an immutable content-addressed blob. The head contains a compact ordered list of blob references and queue metadata. Changed items produce new blobs; unchanged references are shared. `get` assembles the runner checkpoint. `accept` embeds an immutable output record in the accepted item blob, then switches the head with one revision CAS. Readers must use `getOutput` through the committed head. Listing blob rows directly is not an accepted-output API: unreachable candidates can contain uncommitted evidence after a crash or conflict. When documented batch APIs are supplied, reads and initial candidate writes use groups of at most25. Batch writes only stage content-addressed candidates after checking existing bytes; they never publish state. Unchanged blobs are cached per adapter instance and shared between snapshots.

This is atomic **visibility through one head CAS**, not a conditional multi-item transaction. A crash before publication leaves harmless unreachable snapshots. A competing cancellation or takeover advances the head revision and rejects the previous owner's publication. No unconditional batch operation substitutes for CAS. Accepted item snapshots remain immutable across later queue changes; cancellation changes queue metadata without rewriting accepted evidence.

Expiry permits takeover; revision advancement performs actual fencing. The adapter checks the trusted clock immediately before initiating publication. Hedy's conditional write does not support a server-side clock predicate: an already initiated CAS may finish after expiry if no competing head update occurred. External governance revocation is likewise not atomically part of the head transaction; the supervisor must propagate cancellation to the head, and check current governance before every tick. Do not claim stronger clock or external-revocation transaction guarantees.

Every blob and head is limited to 370,000 UTF-8 bytes, below the documented 380KB data item cap. Aggregate state can exceed the cap because blobs are separate records. A single oversized workbook evidence blob fails closed. Initial CAS stages at most25 missing blobs per wake and returns false while initialization is incomplete. The head remains absent until all blobs exist; an absent head means no accepted checkpoint or output. For352 unique rows initialization needs15 wakes. Retries reuse immutable candidates through bounded25-key reads. No private runtime CPU/wall-budget performance has been verified. Supply a bundled SHA implementation to avoid one crypto bridge call per blob, and validate real runtime budgets before enabling the full corpus. Orphan cleanup requires a separately authorized reachability-aware retention policy; this adapter never deletes evidence. Original XLSX financial transport, private profiles, independent QA, and the runtime supervisor remain missing; this store source does not supply them.

Snapshot digests and equality recursively canonicalize object keys while preserving array order, so backend property ordering does not change integrity. Read APIs require stable tenant/root identity; active writes require current authority. Cancellation remains allowed after the same scope is revoked, and must preserve item contents. Run `node --test tests/hedy_financial_store.cjs`. Twelve synthetic tests cover visible acceptance, stale revisions, orphan replay, cancellation during staging, expiry during staging, delayed CAS completion, takeover during final CAS, large aggregate state, unchanged-reference sharing, root isolation, individual row caps, actual runner cancellation after revocation, mutation isolation of assembled reads, and reordered backend object keys. They establish source protocol behavior, not Hedy deployment or real-data analysis.
