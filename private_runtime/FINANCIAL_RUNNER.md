# PRIVATE-DATA-006 — financial extraction runner v1 (source only)

`financial_handler.js` exports a small scheduled-handler factory for an authorized Hedy **staging** installer. The existing project-scoped executor, not this repository lane, supplies `configuration()`, `inventory.list(rootId)`, `queue`, `xlsx`, `independentQA`, and `clock`. No bundled credentials, provider SDK, binary workbook decoder, live root, or deployment authority. The handler is a CommonJS JavaScript module (`require('./financial_handler').createScheduledHandler(dependencies)`), suitable for a scheduled Hedy function; its thin entry stays below the function-size ceiling. Package the two JavaScript source files together. Do not wire this handler to production.

## Installation contract

- Configuration supplies `{client:'jespersen-painting', environment:'staging', enabled:true, rootId:<private opaque ID>}`. The kill switch is `enabled:false`; `cancel({config,store})` persists a terminal stop for this queue. Neither is a provider permission mechanism. The executor owns the exact task authority, installation, revision guard, environment verification, and rollback.
- `inventory.list(rootId)` returns a stable ordered, complete private manifest of at least three `{sourceId,fileId,parentId,sha256}` references. Original-byte hashes are lowercase SHA-256. The executor must bind its inventory snapshot and ensure the authorized root containment server-side; `parentId` checks are defense in depth, not ancestry verification. A manifest change or changed digest requires a new governed queue/version, never a silent overwrite.
- `xlsx.readXlsx(ref,rootId)` is **read-only**, verifies the original workbook byte digest against `ref.sha256` before decoding, and returns an attested `{sourceId,fileId,parentId,sha256,fingerprint,complete,coverage,sheets}` snapshot. `fingerprint` is a versioned private shape identifier; the private transport/adapter must independently validate supported shape/version, exhaustive sheet/row enumeration, and coverage before asserting `complete:true` or any `coverage[category]:true`. `sheets` contains `{name,cells:[{address,value,formula?}]}` with string cell values, optional formula text and cached result in `value`. It must not expose workbook binary to this JS package or public logs. Unknown layout/labels and unsupported categories must be marked incomplete or routed to review, not coerced into a supported shape. This implementation's semantic labels are invented synthetic examples, **not real workbook layout certification**.
- `queue.load()` returns `null` or `{revision,value}`; `queue.cas(expectedRevision|null,nextValue)` is linearizable, returns a boolean, and atomically persists the **entire versioned queue and additive outputs** in governed private storage. It must reject invalid revision, not mutate prior records, and retain private audit history. A handler must have a bounded execution window exceeding its 300-second claim lease or provide a runtime lease extension; stale claims can be reclaimed and fenced via CAS. Claim attempt count is capped at three. No separate output write is allowed. All source identities, fingerprints, formulas, financial facts, QA verdicts and error details remain private. Only aggregate `counters()` may be emitted publicly.
- `independentQA.verify({ref,output,version})` must be a separately owned deterministic runtime QA check, not a self-approval by the runner. It returns `{pass:true,version,sha256}` only after independent financial reconciliation and source/coverage checks; any other response blocks the pilot. The installer must bound its latency, and handle runtime errors without logging private payloads.

## Behavior and limitations

State v1: `PILOT` claims only the first three ordered items; each passes `PENDING -> CLAIMED -> ACCEPTED` only after full extraction, deterministic reconciliation against independently recomputed totals, and independent QA. Fingerprinting/preparation alone never advances the gate. Any pilot `NEEDS_REVIEW` or `FAILED` blocks corpus advancement (`BLOCKED`); three accepted items automatically change phase to `CORPUS`. Corpus failures are isolated. Claims expire, are CAS-fenced, retry at most three times, and replayed accepted outputs are not rewritten. A crash after claim can be retried on lease expiry. External cancellation or kill switch halts work. A fresh governed queue version and new QA are required for remediation of terminal review/failure; no automatic reset of financial decisions.

`extract` requires explicit complete coverage and supporting rows for each computed category, retains original sheet/cell facts separately from formula/cached-result evidence, recomputes monetary amounts using decimal strings and integer minor units, and records source comparisons without overwriting source cells. Payment/outstanding remains unknown without payment rows or coverage, even if a workbook prints a balance. Revenue/profit/margin remain unknown without supporting revenue; zero revenue has undefined margin. Financial values are rounded half away from zero at cents; margin is a percent with two decimal places. Unexpected labels, mixed layouts, unsupported economics, or missing comparison evidence cannot satisfy the pilot. A structural fingerprint is private metadata only and is **not** analysis. QA must independently confirm completeness and semantics before asserting acceptance.

`tests/financial_runner.cjs` and its pytest wrapper use invented synthetic cells/identifiers only. They do not establish actual workbook coverage, independent QA signoff, Hedy deployment, or corpus execution. Rollback: revert these two source files and synthetic tests; the authorized private executor may disable only this task's queue and remove its additive extraction outputs in its governed scope. Original sources remain immutable. Existing Python intake, adapter, schema, and calculation contracts are untouched.
