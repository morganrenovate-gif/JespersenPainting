# PRIVATE-DATA-007 — synthetic-source XLSX evidence contract

Source only. `xlsx_decoder.cjs` accepts a Node Buffer of original XLSX bytes and returns a JSON-serializable `xlsx-evidence/v1` record. No workbook formula is evaluated. `xlsx_provider_adapter.cjs` exports `createAdapter({provider,root,maxAttempts})` with one async `extract({id,parent,version,sha256})` method. Provider must inject **only** `metadata(id)` and `read(id,{maxBytes})`; it must enforce actual ancestry, read-only access, bounded wall-clock deadlines and authorization in the separately governed private installation. The source adapter has no credentials, IDs, tenant settings or network calls. Metadata must return `{id,parent,version,sha256,mime}`; parent must equal configured root. SHA-256/version/metadata are checked before and after byte read and original-byte SHA-256 is checked against expectation. Errors expose generic codes, not private provider payloads. Up to three attempts are permitted for thrown read/metadata failures; stale or malformed responses are never retried.

`decode(bytes)` returns `{version:'xlsx-evidence/v1', sha256, md5, complete:true, worksheets:[{name,cells:[{sheet,address,type,raw,formula,result}]}], nonempty:["Sheet!A1",...]}`. Hashes are lower-case hexadecimal digests of the **original ZIP bytes**, never reserialized XML. `raw` is literal decoded cell content (string, including original numeric spelling) for non-formula cells; formula cells have `raw:null`, original `<f>` text in `formula` (without an invented leading `=`), and separately read `<v>` cache in `result`. A formula cache absent or empty is rejected. String indices are resolved using shared strings and inline/rich text is concatenated without changing the original bytes. Cell type is the XLSX `t` value or `n` by default. Every nonempty cell is included exactly once in both `cells` and `nonempty`; empty styled cells are excluded. Ordering follows workbook sheet and row/cell document order, not inferred economic sections. No actual workbook layout or financial profile is asserted by this record.

Review/rejection codes include `unsupported_layout`, `unsupported_cell`, `missing_formula_cache`, `external_relationship`, `malformed_xml`, `xml_limit`, `archive_limit`, `archive_crc`, `malformed_archive`, `unsupported_archive`, `response_limit`, `source_boundary`, `stale_source`, `provider_read_error`, `configuration_halt`. No partial `complete:true` result is returned on error. Supported subset is a single ordinary workbook with internal worksheet/sharedStrings relations, stored or deflated ZIP entries, scalar cached formulas, shared/inline/plain/rich strings, numbers and booleans. Unsupported extensions, relationships, shared/array formulas, errors, hidden sheets, macros, external entities and unexpected parts require separate review. This is **not** evidence of real-workbook coverage.

Boundaries: input <=8 MiB, <=64 entries, <=2 MiB per entry, <=12 MiB expanded, <=100:1 expansion, XML <=2 MiB per part, <=80,000 XML tokens and <=32 depth, <=40,000 cells, <=32 sheets, output <=12 MiB; CRC32 and ZIP structural checks precede XML parsing. Exact private-runtime installation must separately establish provider ancestry/version semantics, response size/deadline/retry behavior, original byte stability and independent source-profile QA. The v2 financial runner requires a distinct approved `fingerprint` signature and exact profile-bound `{sections,totals,labels,nonempty}` snapshot: this generic evidence **cannot** be passed directly as `extractCells`, and no synthetic signature is an approved profile. A separately authorized private adapter must map every decoded cell to an approved profile or stop for review, preserve immutable bytes and inventory, and validate the profile against private source evidence before staging use. Hedy store transactional acceptance and independent QA remain mandatory and unchanged. No Hedy or provider action is installed by these files.

Synthetic tests: `node --test tests/xlsx_decoder.cjs` (also bridged by `tests/test_xlsx_decoder_js.py` for trusted pytest). Rollback: remove decoder, adapter, documentation and tests. No provider or source state changes.
