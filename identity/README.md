# TIME-002 repository-only identity suggestions

`identity.suggestions.suggest(source, candidates)` returns immutable in-memory review evidence for an `IdentityLabel(namespace, reference, label)` and a tuple of candidates. The only namespaces are `employee` and `job`. References are caller-supplied locators, **not** confirmed mapping IDs; the caller must provide a candidate set for the same review scope and must never interpret absence of a suggestion as evidence that an identity does not exist. Other-namespace candidates are ignored. No provider reads, persistence, API, UI, identity update, confirmation or merge occurs here.

The normalization policy is deliberately narrow: lowercase ASCII words, trim/collapse spaces and tabs. Punctuation, control characters and Unicode are rejected, not guessed away. An exact normalized label match is review-required even if unique. When no exact match exists, a spelling suggestion requires at least two words, exactly one different long alphabetic word (at least five letters on both sides) with the same initial and one insertion, deletion, substitution or adjacent swap; all other words must match. IDs and short names are not fuzzy matched. Multiple matching candidates return ordered evidence with `ambiguous_typo` or `normalized_collision`; duplicate in-namespace candidate references (including the source reference) and malformed inputs raise `ValueError` rather than selecting an identity. One-word source labels return `no_suggestion/insufficient_label`. No matching evidence returns `no_suggestion/no_supported_match`. All suggested candidates carry their source reference, original label, normalized label and stable reason (`normalized_equal` or `single_typo`). Every candidate-bearing result has state `needs_review`, never confirmed. This is a heuristic, not a confidence probability or a guarantee of identity.
