# ECON-001/002: job economics source evidence and findings v1

`job_economics.model.JobEconomics` is a frozen, versioned **in-memory** envelope for one caller-supplied opaque job ID. Its eight required slots implement the backlog's seven input groups with time and labor cost deliberately separated: estimate, change orders, time, labor, materials, invoice evidence, QuickBooks facts, and historical workbook facts. Each `SourceEvidence` retains coverage (`available`, `missing`, `needs_review`, `stale`, `error`) and its own records; each record retains category, source ID, record ID and individually stateful facts with opaque field locators. Identical IDs or values across categories are not a join key. No normalization, identity matching, deduplication, calculation, or source-of-truth promotion occurs here. In particular, invoice evidence is not QuickBooks accounting truth; missing is not zero and stale records are not fresh facts.

Historical workbook records may reference an existing `job_cost.schema.JobCostDocument`, preserving its workbook ID/hash, raw fact provenance, formulas, derived metrics and discrepancies **within that source**. The reference must match the record's source ID. This envelope does not copy workbook totals into other slots or use workbook calculations as accounting facts. Fact IDs are unique within an evidence record only; composite identity is category + source ID + record ID. Callers must explicitly supply category coverage, even when no records exist.

## Explicit findings (ECON-002)

`find_evidence(job, links=())` produces deterministic, immutable `EconomicsFindings` without modifying the eight source slots. A caller must supply each `ComparisonLink(FactRef(...), FactRef(...), comparable_field)`; each `FactRef` identifies category, source ID, record ID and fact ID. No link is generated from matching labels, IDs, values or the job ID. A dangling reference fails closed. A conflict is reported only for distinct sources when **both facts are present**, both literal `field` names equal the caller's `comparable_field`, both values have the same type (text or Decimal), and their values differ. No coercion, units/currency conversion or tolerance is assumed: the caller is responsible for establishing semantic comparability and linkage. Non-present facts and mismatched fields/types do not produce conflicts. Repeated or reversed links yield one finding, with source references in canonical order; source records are never deduplicated or overwritten. `ConflictFinding.link` traces back to the original facts and their locators/values, not to a new accounting value. QuickBooks remains accounting source of truth.

`CoverageFinding` lists each non-available category (`missing`, `stale`, `needs_review`, `error`) even if there are no records; for retained records it lists full fact references, including non-present facts. These references point back to original source states and locators. Stale/error retained facts are **not** marked fresh; a conflict involving a retained stale fact does not erase the stale coverage warning. The findings are a snapshot of the passed envelope, not a sync monitor or persisted claim of current provider health. There is no cross-source derived total or margin in this API.

Tests in `tests/test_job_economics_model.py` and `tests/test_job_economics_findings.py` are **invented synthetic examples only**. They cover source separation, explicit differing/equal/unlinked/non-comparable comparisons, coverage and immutable source records. A trusted workflow can run `python -m unittest discover -s tests`; no test execution, live-data validation, deployed acceptance or production capability is claimed by this document.
