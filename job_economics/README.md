# ECON-001: job economics source evidence v1

`job_economics.model.JobEconomics` is a frozen, versioned **in-memory** envelope for one caller-supplied opaque job ID. Its eight required slots implement the backlog's seven input groups with time and labor cost deliberately separated: estimate, change orders, time, labor, materials, invoice evidence, QuickBooks facts, and historical workbook facts. Each `SourceEvidence` retains coverage (`available`, `missing`, `needs_review`, `stale`, `error`) and its own records; each record retains category, source ID, record ID and individually stateful facts with opaque field locators. Identical IDs or values across categories are not a join key. No normalization, identity matching, deduplication, calculation, or source-of-truth promotion occurs here. In particular, invoice evidence is not QuickBooks accounting truth; missing is not zero and stale records are not fresh facts.

Historical workbook records may reference an existing `job_cost.schema.JobCostDocument`, preserving its workbook ID/hash, raw fact provenance, formulas, derived metrics and discrepancies **within that source**. The reference must match the record's source ID. This envelope does not copy workbook totals into other slots or use workbook calculations as accounting facts. Fact IDs are unique within an evidence record only; composite identity is category + source ID + record ID. Callers must explicitly supply category coverage, even when no records exist. No evidence freshness timestamps, cross-source conflict policy, input-traced cross-source totals, storage or provider adapter is supplied; these belong to later separately validated work (ECON-002 and integration lanes).

Tests in `tests/test_job_economics_model.py` are **invented synthetic examples only**. They exercise all categories, duplicate numerical values and local fact IDs across sources, stale/missing/error coverage, independent immutable updates, job-cost document linking and invalid-source rejection. A trusted workflow can run `python -m unittest discover -s tests`; no test execution, live-data validation, deployed acceptance or production capability is claimed by this document. This is repository-level progress toward the source-separated job economics requirement in `ACCEPTANCE.md`, not a claim that its checklist item passes in staging. Rollback: remove this model, tests, and document; there is no migration or external state.
