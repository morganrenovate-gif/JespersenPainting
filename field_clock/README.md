# TIME-003 — field clock, repository-only synthetic preview

Open `field_clock/index.html` for the single-assignment preview; use `?example=multiple` for the selector. Both use invented jobs and in-memory callbacks only. The preview deliberately says no time record is saved. It is **not** an authenticated employee application, production time capture, a provider integration, or staging acceptance. The repository contains no existing field-clock frontend/runtime to wire into; later authorized integration must supply already-authorized current assignments and capture callbacks that acknowledge success (Clock In returns a valid `Date`, Clock Out resolves only after capture). Failed callbacks leave the displayed state unchanged with a worker-safe retry message. No provider/accounting metadata is rendered; job `id` is used only for callback identity. No offline/pending-sync claims (TIME-004).

UI-STD-1.0 assignment: Product Jespersen Painting Intelligence; surface field employee mobile clock; dominant Industrial Operations, secondary Digital Blueprint; Jespersen semantic tokens in `clock.css`, compact density, LOW motion; users field painters/crew; critical information job, selected choice where necessary, clock state, elapsed/start time and next action. Mobile keeps one full-width action and stacked selector rows; desktop narrows the same task lane rather than adding a dashboard. Safe-area padding, minimum 60px targets, focus outlines, semantic text states and reduced-motion behavior are intentional. No decorative cards, gradient or invented telemetry; running counter is derived from the acknowledged start time. Design review: product fit (one task), hierarchy (state/job/action), density (compact rows), identity (worksite rule/grid language), motion (none), structure (continuous lane), data (tabular clock), responsiveness (stacked on phones), accessibility (text states, native buttons), anti-generic (no KPI dashboard).
