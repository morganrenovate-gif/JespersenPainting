# EST-002 estimator interpretation boundary (repository-only)

`estimator.boundary` consumes the immutable `painting-takeoff/v1` scope vocabulary from `estimator.taxonomy`. It does not parse documents or use an AI provider. An `InterpretationProposal` is always `needs_review`, with an opaque source locator and optional *suggested* dimensions; these are not measured inputs. The locator is a caller-supplied reference, not proof that source evidence exists.

The explicit transition is `approve_measurement(proposal, review)`. A reviewer must supply a `MeasurementReview` with `approved` decision, matching proposal ID and evidence locator, a nonempty reviewer reference, and independently checked positive finite Decimal dimensions in feet. Corrections need not match suggested dimensions. Rejection, mismatch, missing/invalid values, unknown scope or an unspecified finish fail closed. Only a ceiling with a declared finish is supported; the finish is an intent, not validated applicability. The resulting immutable `ReviewedMeasurement` retains proposal, evidence locator and reviewer references; its constructor is gated for ordinary callers. The pure `calculate_ceiling_area` function accepts only that type and returns a versioned rectangular area in square feet; it does not consume suggestions. No perimeter, openings, walls, door counts, exterior areas, scale, or other plan geometry is inferred.

There is **no path to financial or accounting truth** in this contract: no rates, pricing, labor/material prediction, job-cost totals, money fields, or integration with `job_economics` / QuickBooks. A reviewed dimension is still a reviewer assertion, not a certified plan measurement; this in-memory gate is not an authorization/security boundary and does not authenticate reviewers or persist an audit trail. A future runtime must verify evidence and reviewer authority and preserve the review record before accepting actual plan measurements. Immutable Python objects can be forged by hostile code; do not use these types as a security check on untrusted serialized inputs. `tests/test_estimator_boundary.py` uses invented synthetic identifiers/dimensions to exercise the boundary; it does not establish real-plan coverage, accuracy, completed-job backtest, staging/deployed acceptance or financial validation. No user-facing surface or provider action is added.
