# EST-003 synthetic estimator backtest protocol (repository-only)

`estimator.backtest.compare(plan, predicted, actual)` takes **invented synthetic** `PlanSet`, `PredictedTakeoff`, and `CompletedActuals` records (example: `tests/test_estimator_backtest.py`). Run `python -m unittest discover -s tests -p 'test_estimator_backtest.py'` from the repository root. No plan files, provider access, workbook, runtime, or other data source is read. This is not a real completed-job backtest.

## Matching / evidence contract

- All three records must explicitly share the same nonblank `job_ref` and exact `plan_ref` (plan-set revision). These are caller-supplied opaque identifiers, not authenticated or verified source identity. `CompletedActuals` must be labeled `completed`; this label alone does not certify completion.
- The plan enumerates a nonempty set of unique `scope_id`s with `PaintingScope` (EST-001 taxonomy), scope unit and plan evidence reference (e.g. sheet/room locator). Prediction and actual each require **exactly** those scope keys, identical taxonomy category/declared finish and unit, one labor row per scope, and at least one material row per scope. Material rows match by `(scope_id, material_id)` and exact unit; both sides must have the same keys. No mapping by name, guessed equivalence, unit conversion, zero-filling, dropping unmatched rows, or partial comparison occurs. A reported zero is an explicit Decimal zero, not missing evidence.
- Plan, predicted and completed records retain their own nonblank evidence references, as does every quantity row. The report retains record-level prediction/actual references and for each variance the plan-scope reference plus both quantity-row references. References are locators supplied by the caller; this harness does not inspect source contents or verify that a reference resolves. A future real workflow must authenticate, review and link the completed plan set and completed-job actuals outside this public repository.
- Missing, duplicate, unexpected, mismatched, uncompleted or malformed evidence raises `ValueError` and **produces no comparison report**. Each side must have nonempty tuples of rows. Decimal quantities must be finite and nonnegative; other numeric types (including floats) are rejected. Units are exact identifiers; a declared finish is not verified finish applicability.

## Variances / units

`BacktestReport` sorts scope/labor rows by `scope_id`, material rows by `(scope_id, material_id)` for repeatable ordering. Each `Variance` reports the key, unit, predicted, actual and **actual minus predicted** as Decimal, with evidence references. A negative result means the completed synthetic actual is smaller than the synthetic prediction. Scope units supported here: `sq_ft` (area), `linear_ft` (length), `count` (items). Labor is in `hours` per scope. Material units supported: `gallon`, `each`, `linear_ft` per material per scope. Values are compared only within matching units; no derived production rate, aggregation across units, conversion, cost, pricing or monetary calculation exists.

This module accepts supplied quantities; it does not interpret plans, invoke `estimator.boundary`, generate predictions, validate reviewer authority, or become financial/accounting truth. The synthetic fixture demonstrates the **protocol only**; it is not evidence of real-plan coverage or actual estimating accuracy. A real acceptance PASS still requires a complete matching completed plan set and independently sourced completed-job actuals in an authorized environment, with independent QA. No user-facing surface or production deployment is included.
